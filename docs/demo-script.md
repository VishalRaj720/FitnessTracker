# Demo script (8 minutes)

## Setup (before judges arrive)

- Laptop with webcam on a stand at hip height, ~2.5 m of clear floor, side-on marker on the floor (tape).
- Laptop → projector/TV mirrored. Chrome open on `http://localhost:5173` (camera works on localhost without HTTPS).
- Backend running locally (`uv run uvicorn …` or `docker compose up`) — **no internet required**.
- Phone with the PWA installed and logged in as `demo@fitsathi.app`.
- Fresh demo DB: `rm backend/fitsathi.db && uv run python -m scripts.demo_data` (the demo account's plan then shows "+1 squats — two good sessions").
- Second laptop with the same setup as hot spare.
- Rehearse once with the lights of the venue.

## If something breaks

1. Camera permission / bad light → **Use manual mode** button; continue the flow; say "manual minutes never count as verified — that's the point."
2. Venue Wi-Fi dead → nothing depends on it. Backend is local; phone works offline and syncs later.
3. Webcam dead → switch to phone camera in Chrome for Android (needs HTTPS: pre-deploy to Vercel or run `npx localtunnel --port 5173` before the session).
4. Pose model won't load (WebGL) → it falls back to CPU automatically (~12 fps, still counts).
5. Everything dead → 90-second screen recording of the full flow on the spare laptop.

## Q&A prep

- **"Why not a native app?"** Camera + pose runs at 30 fps in the browser; one codebase gives PWA, APK (Capacitor) and the dashboard. Zero install friction for 10,000 institutes.
- **"Is the ML yours?"** The pose model is pretrained (MediaPipe). Our contribution is the exercise engine, verified-minutes model, and the adaptive rules — all tested and deterministic. No training data needed on day one; recorded landmark fixtures make it improvable.
- **"Privacy?"** No frame ever leaves the device. Server stores reps, timings, scores. Dashboard is aggregate with k-anonymity.
- **"Cheating?"** Only camera-verified minutes count; server re-checks completion ratio, visibility and rep rate.
- **"Scale?"** Inference cost is ₹0 (on-device). One FastAPI + Postgres handles a campus; Redis + workers when it's a state.
